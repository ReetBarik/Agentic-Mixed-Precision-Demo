# WAVE3 DEDUP — TU-global symbol dedup across shims

**Date:** 2026-07-21 · fixes the structural collision in
`runs/qcdloop/WAVE3_CHARACTERIZATION_2026-07-21.md` (72/79 `llm_gen_failed` are
`redefinition of struct ql::Constants<T>` or a `ql::` helper — one definition per
TU per signature is allowed, the Patcher emitted one per region).

## Design decisions (settled BEFORE implementation)

### Q1 — where the merge happens: **B (integrator-side, shared engine `regional.py`)**

The merge needs exactly three things, and all three already live in
`agents/integrator_base/regional.py::run_integrate_region`:

1. **the new shim's content** — the LLM output (`shim_body`) is produced here;
2. **the current TU state** — reachable through `repo_path`, which the Patcher has
   already `reset_hard`-ed to `parent_sha` (the committed candidate of the
   previous region), so every prior region's committed shim is on disk when this
   region generates (`agents/patcher/agent.py:158`);
3. **control of both the shim install and the boundary `#include` name** —
   `_install_in_tree` and `_boundary` are both called here.

The Patcher processes one intent at a time and carries **no** cross-region state
except the git tree (`agent.py` resets and commits per intent). So patcher-side
(A) would have to (a) re-derive the shim structure it never parses today, and (b)
rewrite the boundary `#include` the integrator *just* emitted — strictly more
surgery, further from where the shim knowledge lives. Putting the merge in the
shared engine also gives dd/ff/float the fix for free, since
`agents/{dd,ff,float}_integrator/agent.py` are thin wrappers over
`run_integrate_region`.

### Q2 — the C++ shape of a merge: **2a (one merged specialization per (TU,T), generalized to one deduped definition per TU-global signature)**

A C++ class-template specialization is a single *closed* definition — you cannot
add a member to `Constants<ddouble>` after it is defined. So 2b ("empty spec +
later free-function forwarders") still requires rewriting the first lander's
struct to add the forwarding members, and only adds a layer of indirection: it is
strictly more surgery for the same rewrite, and it risks leaking `_name_dd()`
free functions. 2a keeps the app-visible API identical — `Constants<T>::_ieps50()`
resolves to a real member of the one specialization — and generalizes cleanly:
`ql::` free-function helpers (`ql::Real`, `ql::Lnrat`, `ql::iszero`) and
cross-namespace bridges become dedup-by-signature entries in the same artifact.

Concretely, 2a is realized as a **canonical per-family shim** (`ql_shim_dd.h` /
`ql_shim_ff.h` / `ql_shim_float.h`) at the tree root. Every region of that family
merges its generated symbols into that one file — specialization members are
**unioned** across regions (keyed by member signature), and free functions /
namespace blocks are **deduped by signature** (keep-first: the already-committed,
already-validated definition wins). `#pragma once` guarantees one definition per
TU. The per-family scope is TU-safe because it is a *superset* of any single TU:
even if two genuinely-separate TUs existed, each would `#include` the canonical
file and see exactly one definition of every symbol.

_(No mid-implementation change to either decision.)_

## What actually changed (mechanism)

`agents/integrator_base/regional.py::run_integrate_region` no longer installs a
*per-region* shim into the candidate tree. It still writes the per-region shim to
`out_dir` (forensics + SOURCE_HASH cache, so `shim_paths[0]` is unchanged), but it
now **merges** that generated shim body into a single canonical per-family shim in
the tree (`ql_shim_dd.h` / `ql_shim_ff.h` / `ql_shim_float.h`) via the new
`agents/integrator_base/shim_merge.py`, and the deterministic boundary patch
`#include`s that canonical file. The merge is a brace-aware chunker (not a full
C++ parser) that:

- unions `#include`s (keep-first, order-preserving);
- groups `template<> struct NAME<T>` specializations by normalized `T` (leading
  `::` and whitespace ignored, so `Constants< ::quad::ddfun::ddouble >` and
  `Constants<quad::ddfun::ddouble>` collapse) and **unions their members** by
  member signature;
- dedups free functions by `(name, arg-types)` with parameter *names* stripped
  (so `Max(ddouble a, ddouble b)` and `Max(ddouble x, ddouble y)` are one);
- recurses into any namespace (not just `ql`), so cross-namespace bridges dedup too;
- renders forward declarations before specializations (a spec of an undeclared
  primary would not compile);
- is **keep-first**: the already-committed (already-validated) definition wins on
  a duplicate. Nothing is keyed on the name `Constants` — the mechanism dedups any
  TU-global symbol a shim emits at namespace or specialization scope.

`_install_in_tree` (the old per-region installer) is removed.

## Ready-for-next-lever check

**The misgen classifier at `dispatch.py:67` is no longer clearly the right next
lever.** Its two purposes were (a) re-tag `redefinition` as a structural collision
rather than `llm_capacity`, and (b) short-circuit the deterministic collision retry
(pure wasted attempts + backoff). Dedup makes (b) **moot** — there are no more
deterministic collisions to retry — and (a) becomes low-value telemetry for a
cluster that no longer fails. In short, dedup **subsumes** most of what the
classifier was scoped to do.

Recommendation: **run a faithful dedup 10k first to re-measure the residual**, then
re-scope. The post-dedup residual is predicted to be the 3 C-R4 transcendentals
(plus any merge-induced surprises), which want a *transcendental/manual-
classification* lever, not a collision classifier. Do not pre-commit to the
`dispatch.py:67` work until that 10k shows what actually remains. (`is_retryable_misgen`
was left untouched this pass, as instructed.)

- **Do not treat these as `llm_capacity`** — 0/79 are capacity/rate-limit/refusal.

  assembly (`regions_at_dd_ceiling = 0` is correct).

New this pass:

- **Do not re-introduce per-region shim installs into the tree.** The tree carries
  ONE canonical shim per family; per-region shims live only as `out_dir` artifacts.
  Two regions installing full specializations is exactly the collision.
- **Do not touch `dispatch.py:is_retryable_misgen` yet** — re-scope it (or drop it)
  only after the dedup 10k re-measures the residual.
- **Do not run the 10k in this pass** — the next 10k measures dedup (+ whatever the
  re-scoped follow-up turns out to be) together.
- **Do not assume the merge is a full C++ parser.** It is a brace-aware chunker
  tuned to the shim format; the build gate remains the ground-truth backstop (a
  bad merge fails the build and is retried like any misgen). If a future shim
  shape defeats the chunker, widen `shim_merge.py`, do not bypass the merge.
