# Phase 2b — Scorer: measurement/decision split + per-`(region_id, rung)` manifest

Branch `phase2a-fanout` (continues off Phase 2a). Ships the fix to **Blocker #2**
(whole-app Validator attribution): the Validator no longer collapses the whole
application to one min-precise-digits number and stamps one pass/fail verdict per
intent. It now **measures** the app-level error *attributable to each region at each
rung* and emits it as a manifest of `(region_id, rung) → delta` cells. The
**decision** (accept/reject) is left to downstream consumers — today's loop still
gets its unchanged verdict; a future collapsed solver reads the manifest.

The scorer emits **no verdicts**. It is a pure reduction over the candidate +
DD-reference coeff arrays the Validator already builds, so it adds **no wall-clock**.

## The reframe

Before: one region moved to `dd` that drops its integral's relative error to ~1e-13
was compared against the **whole app's** min — set by cancellation in a *different*
integral (B12, rel-err **2.0e-4**) — and stamped `insufficient_fix`. The
measurement level (app) was right; the decision level (per intent) was wrong.

After: the same promotion is scored on **B1's own** output (rel-err **6.9e-13**),
un-buried from B12's 2e-4. No verdict is applied in the scorer; the cell is the
artifact a solver acts on.

## What ships

- `agents/validator/scorer.py` — the scorer service:
  - `canonical_region_id` (== Strategy's `RegionTarget.location`, so **no
    canonicalization step was needed** — see handoff), `rung_from_kind`.
  - qcdloop output reduction: max relative error across the six Laurent components
    (eps^-2 / eps^-1 / eps^0, real+imag) per sample, scoped to the region's
    integral(s); default reduction is identity (scalar output).
  - `delta_random` / `delta_adversarial` split (adversarial `null` when the tail is
    empty — the 2b stub), `delta_effective = max(...)`.
  - `baseline_delta_*` — the unpatched working-tree app at the same scope, so patch
    **inertness** is a one-field read (`delta_effective == baseline_delta_effective`).
  - `baseline_id` (hash of `baseline_spec` + app source + DD-oracle source) and
    `battery_version` (hash of the random+adversarial slices) — the cache key.
  - `ManifestRow` schema + JSONL writer/reader/round-trip (forward-compatible: an
    unknown future field is preserved, not dropped), `collapse_min_delta`
    (over-generation → min delta per key), status enum + Patcher-status map,
    `rows_from_iteration_log` + `assemble_manifest` for the un-measured cells.
- `agents/validator/validate.py` — thin wrapper: additive params (`cell`,
  `scorer_manifest_path`, `iteration_id`, `baseline_spec`); computes the measured
  cell as a **documented side-effect artifact** and echoes it under an additive
  `"scorer"` verdict key. Verdict gates + returned keys otherwise **unchanged**.
- `agents/validator/agent.py` — `make_validator_fn` forwards the `scorer_cell`.
- `agents/strategy/agent.py` — `_invoke_validator` attaches the
  `(region_id, rung, intent_id, integrals)` cell descriptor from the intent + region
  record. No graph-topology change (extract-later is accepted debt).
- `runs/qcdloop/run_all_integrals.py` — writes the scored manifest per pass and
  assembles the full manifest (measured + `patcher_failed`/`build_failed`/
  `wire_failed`), recording its path in the pass manifest.
- `runs/qcdloop/analyze_2b_manifest.py` — the 2a-verdict vs 2b-delta comparison.

## Manifest row schema

`region_id` (**primary key**), `rung`, `iteration_id`, `status`
(`measured` / `not_a_candidate` / `patcher_failed` / `build_failed` / `wire_failed`),
`delta_adversarial`, `delta_random`, `delta_effective`,
`baseline_delta_{adversarial,random,effective}`, `baseline_id`, `battery_version`,
`intent_id`, `integrals_scope`, `patcher_metadata`, `schema_version`.

Reading:

- **The reframe works.** Every region 2a stamped `reject / insufficient_fix` now
  carries a **concrete, un-buried delta** (6.9e-13 — B1's own error), not the
  whole-app floor (B12's 2.0e-4) the old verdict rejected against.
- **6 speedup cells are `patcher_failed`** (the float/ff `llm_gen_failed` gap) —
  clean signal feeding the float-hardening backlog as a work queue.
- **Honest surprise (see handoff): the 8 measured deltas are bit-identical across
  `dd`/`ff`/`float` and equal `baseline_delta`** — i.e. the candidate B1 output is
  bit-for-bit the unpatched baseline. The patches compile, wire, and execute (2a
  proved that), but they are **numerically inert on B1's output** at these regions.
  The finer-grained scorer surfaces a no-op residue the whole-app min never could;
  `baseline_delta` makes it a one-field read. This is *measurement working as
  intended* — a solver would correctly decline to credit an inert patch.

## Baseline cache

The DD-instantiated whole-app reference and the pure-double current baseline are
cached per `(source hash, snapshot)` (`runs/qcdloop/validator/cache/`). The 2b run
reused both (`dd_2229ec4…_seed12345_n5000.pkl`, `current_2fac6c8…_n5000.pkl`), so
the scorer added no baseline builds — the second B1 run's baseline cost was **0**.
The scorer's own `baseline_id` / `battery_version` mirror this key at the cell level
(unit-tested: hit iff `baseline_spec` + app source + battery unchanged).

DD-instantiated whole-app cost (one-time, first build+run, measured at n=2000 on an
uncached snapshot so the demo cache stayed intact): **~11.9 s build + ~4.0 s run =
15.9 s**, vs pure-double **~8.3 s build + ~0.8 s run = 9.1 s**. DD arithmetic is
~5× slower per sample (4.0 s vs 0.8 s); the build is comparable. This whole cost is
paid **once per run** and amortized across all 14 candidates by the cache.

## Handoff notes for Reet

1. **Surprising field / schema deviation.** I added `baseline_delta_*` (a pure
   measurement attribute, additive to the minimum-viable schema). It was worth the
   deviation: the 8 measured deltas came back *bit-identical across rungs*, and
   `baseline_delta` proved why — the candidate B1 output equals the unpatched
   baseline. Without it, the identical deltas look like a scorer bug rather than the
   real signal (patches numerically inert on B1). **Recommend the next investigation
   be "why inert": is it region inactivity (these shared-header lines don't flow
   into B1's dominant error) or a residual float/ff no-op on the regional path?**
   The manifest now makes that question first-class.
2. **Baseline runtime cost on B1.** DD-instantiated whole-app: **15.9 s** (11.9 s
   build + 4.0 s run at n=2000) vs pure-double **9.1 s** (8.3 s + 0.8 s) — DD is
   ~1.7× end-to-end, ~5× on the run alone. Cached per `(source hash, snapshot)`, so
   it is a one-time per-run cost; the 2b demo paid **0** (cache hit). At n=5000 the
   DD run is ~10 s. This is comfortably affordable as a per-pass baseline.
3. **region_id stability.** No canonicalization step was required. `region_id` is
   byte-identical to Strategy's `RegionTarget.location` (`"file:line"` /
   `"file:start-end"`), which derives purely from the characterization report key and
   is invariant to Patcher runs and fan-out over-generation (variants change, the
   region does not). Unit-tested against `RegionTarget.location`.
4. **Joint measurement → Phase 2c or later?** Recommend **later**, not 2c. Solo max
   is a documented lower bound on the joint max, but 2b shows the more urgent gap is
   *numerical effect* (inert patches), not joint interaction — a solver has nothing
   to jointly optimize until patches move the needle. Sequence: (2c) close the
   inert-patch / float-gen gap so deltas discriminate rung, then (2d) joint
   measurement once single-region deltas are trustworthy.
