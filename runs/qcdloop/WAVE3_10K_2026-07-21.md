The shims are generated and merged correctly and `#include`d into the app headers, but **the deterministic boundary patch — which owns every region-local precision rewrite — never lands in any commit.**

**Root cause (high confidence): commit `e11b788` ("patcher: dedup TU-global Constants<T> …").** Its refactor of `agents/integrator_base/regional.py` changed the engine so it "no longer installs a per-region shim into the tree" and instead merges symbols into one canonical shim that "the boundary patch #includes." The shim-merge half works; the boundary-application half was severed. This violates the standing contract *"Fix-C returns [] on vanilla so boundary owns region-local writes"* — with the boundary write gone, the first region per family installs the merged shim + include, and every subsequent region has nothing new to commit → `NothingToCommitError` → `empty_candidate` (222 of them; baseline had 0).

Coverage was traded for the clean failure count.

**Consequence for the hard floors:** tolerance rejects / strategy_bugs / commit_failed / tail failures are all **still 0** — but only because the regression manifests as silent no-ops (`empty_candidate`), not as bad commits. A green floor here does **not** mean a healthy run.

**Required next step (Wave-4 pass 0, before any lever work):** root-cause and fix the boundary-patch application in `regional.py` / `shim_merge.py`, add a regression guard that asserts a committed demotion produces a boundary-conversion hunk (not just an include), then re-run this 10k. The dedup structural work itself (Section E) is sound and should be kept.
