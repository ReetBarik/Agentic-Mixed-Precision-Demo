# Phase 2a — Patcher call-graph fan-out (regions only)

Branch `phase2a-fanout` off `langgraph-agents`. Ships the fix to **Blocker #1**
(numerical no-op): when Strategy accepts a regional modification, the Patcher now
emits **per-caller-path function variants** instead of a `Constants<T>`
type-specialization shim that the plain-`double` build never references.

Blocker #2 (whole-app Validator) is Phase 2b and is unchanged here — so rejects
still dominate a B1 run, exactly as predicted.

## What ships

- `agents/patcher/call_graph.py` — libclang builds the authoritative function
  **definition set + extents** rooted at the integral entry point; call **edges**
  come from a comment/string-aware **token scan** over each function body, because
  qcdloop's dispatch is dependent template calls (`ql::B1m<T...>(...)`) that
  libclang drops from the AST (verified: the compound-statement bodies come back
  empty). Fails loud (`CallGraphError`) on an empty parse rather than returning a
  silently edge-less graph.
- `agents/patcher/variant_naming.py` — deterministic bottom-up names
  (`f_g_h_B1`), collision assertion; isolated so it can be swapped for
  hashed-with-manifest later.
- `agents/patcher/fanout.py` — enumerate every caller-path root→f; render each
  variant deterministically from a spec (copy original, promote the region inline
  via `boundary.promote_region_block`, reroute child calls, rename def+self-calls);
  merge-aware per-file `AMP-FANOUT` block whose manifest comment is the source of
  truth, so the fan-out is **stateless across intents** and shared-prefix intents
  converge onto the same intermediate variant. Entry point is never renamed — its
  body is rerouted in place (its call site is in the shared read-only driver); a
  region *in* the entry point is promoted in place.
- `agents/patcher/gates.py` — variant-wiring gate: every declared variant must be
  **referenced** (an orphan = a broken reroute = silent bypass), which is reliable
  even though the KOKKOS_INLINE template variants usually inline away and emit no
  `nm` symbol; `nm` presence is kept as telemetry.
- `agents/patcher/{dispatch,agent}.py` — regional intents route to fan-out when a
  `FanoutSettings` is wired (per-pass, `--fanout`); the classic shim+boundary path
  is preserved as default and as the fallback when a region isn't in a
  resolvable/reachable function.
- `agents/per_integral_orchestrator/manifest.py` — preserves `patcher_status` +
  `verdict_reason` and classifies/tallies the new failure modes
  (`call_graph_build_failed`, `variant_name_collision`,
  `rename_cascade_incomplete`, `silent_bypass`) from the per-iter error excerpts.
- `runs/qcdloop/run_all_integrals.py` — `--fanout --entry-point BO
  --fanout-max-paths N`.

## Tests

`tests/patcher/fanout/` — 30 tests: call-graph resolution + multi-path enumeration
(fan-in on `g` and `f`), variant naming (determinism + collision), rename cascade
(variants/reroutes/in-place root/originals untouched), multi-intent shared-prefix
merge, byte-identical over-generation (both generated, no dedup), symbol/wiring
gate (source-level orphan guard + nm telemetry). Full suite: **454 passing**.

## B1 end-to-end

### Compile de-risk probe (`runs/qcdloop/fanout_build_probe.py`)

Isolates the single biggest Phase-2a risk — *does the copied-variant + shim tree
actually compile and wire?* — from the expensive whole-app Validator. It clones the
base headers, builds the BO-rooted call graph, runs the **real** dd integrator (LLM)
to install the shim, fans out one B1 region, then runs the **real** vanilla cmake
build gate + the variant-wiring gate.

Run `B0m.h:126 --which dd` (region resolves to function `B1`):

| Stage | Result |
|-------|--------|
| dd integrator (real LLM) | `ok`, 6626 tokens, 11.8 s |
| Fan-out | 2 variants `['B0m_B1', 'B1_B0m_B1']`; 1 caller-path; `in_place=False`; touched `B0m.h`, `boxGPU.h` |
| **Vanilla build gate** | **`ok` (8.6 s)** |
| Variant-wiring gate | `OK` (every declared variant referenced) |
| `nm` symbols | `B0m_B1` present; `B1_B0m_B1` inlined away (expected for the KOKKOS_INLINE template variant) |

This run is also the **topological-emission regression in the field**: the two
variants are exactly the caller/callee pair `B0m_B1` → `ql::B1_B0m_B1<...>` whose
name-sorted emission (`B0m_B1` sorts before `B1_B0m_B1`) put the *caller first* and
broke the vanilla build. A qualified template-id is looked up at definition time
(not deferred like an unqualified dependent call), so the callee must be defined
earlier; `_topo_order` in `fanout.py` now emits callees first and the build passes.
Guarded by 3 tests in `tests/patcher/fanout/test_cascade.py` (fan-out suite: 33).

_Cross-device note:_ the probe clones with `--no-hardlinks` because `--out` lands on
`/tmp` (a different filesystem from the base repo under `/home`), where `--local`'s
object hardlinks fail with `Invalid cross-device link`.

### Full B1 fan-out pass (`run_all_integrals.py --integrals B1 --fanout`)

```
--report report_5k.json --integrals B1 --sample-count 5000 --tolerance 10
--fanout --entry-point BO --out-dir per_integral_out_b1_fanout --clean
```

Result: `status=budget_exhausted`, **14 intents attempted, 0 accepted, 14 rejected**,
14 iterations, wall 676 s (11.3 min), disk 27.5 MB.

Breakdown by patcher outcome (`manifest_B1.json` → `failure_modes` / `decisions`):

| # | Intent | Rung | patcher_status | verdict | verdict_reason |
|---|--------|------|----------------|---------|----------------|
| 8 | correctness | `double-to-dd` | `ok` | reject | `insufficient_fix` |
| 6 | speedup | `double-to-float` | `llm_gen_failed` | reject | *(never validated)* |

**No fan-out-specific failure mode fired** — zero `call_graph_build_failed`,
`variant_name_collision`, `rename_cascade_incomplete`, or `silent_bypass`. The
call-graph fan-out machinery (build → enumerate → render → reroute → merge → topo
emit → wire) is sound end-to-end in a real pass, not just the single-region probe.

The 8 correctness patches are the important signal: they generate cleanly, compile,
wire, and sit on the executed path (`driver → BO → rerouted body → B0m_B1 →
ql::B1_B0m_B1`), yet the Validator returns `insufficient_fix`. That is a *numerical*
verdict ("ran, did not reach the 8-digit floor"), **not** the Blocker-#1 no-op
("bit-identical to baseline"). Blocker #1 is fixed; what remains is measurement.

## Honest limits surfaced

1. **Blocker #2 (whole-app Validator) is the whole residual gap** — confirmed, and
   now cleanly isolated from Blocker #1. Fan-out produces genuine, executed,
   precision-promoted code (the probe proves compile + wiring; the pass proves the
   Validator measures a real numerical result), but a per-integral dd promotion is
   scored against the *whole application's* min-precise-digits. B1 is already
   `stable` in the report (max_rel_err ~1.7e-9); the global floor is set by
   cancellation in other integrals, so every B1 correctness patch is
   `insufficient_fix` no matter how correct it is. Phase 2b = caller-scoped /
   per-integral validation so a B1 patch is judged on B1's output.

2. **Float/speedup rung Patcher-gen robustness** — 6/6 speedup intents
   (`double-to-float`) came back `llm_gen_failed` before reaching the Validator. This
   is a Patcher generation gap on the float direction, independent of fan-out and of
   Blocker #2; it needs its own prompt/gen investigation (cf. the `_ieps50`
   gen-robustness pattern in earlier waves).

3. **`budget_exhausted`, not convergence** — the pass stopped because the 14-intent
   correctness-drain budget ran out with 0 accepts, not because B1 was solved. With
   Blocker #2 open this is the expected terminal state for a B1 run; it is not a
   regression and not a fan-out defect.
