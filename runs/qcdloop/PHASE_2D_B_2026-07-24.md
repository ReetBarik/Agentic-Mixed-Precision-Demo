# Phase 2d-B — write-boundary-truncation detector gate

Adds a static detector that converts the **write-boundary-truncation INERT** class
(surfaced by Phase 2d-A) into a *cheap terminal failure* — `write_truncation` — before
paying a build, the UPCAST analogue of Phase 2c's `promotion_no_op` (empty payload).

## What it detects

`agents/integrator_base/boundary.py::write_truncation_inert(region, reads, writes,
two_limb, *, caller_type, complex_tokens, caller_complex)` fires iff **all** of:

1. **`two_limb`** — an UPCAST (ff / dd).  A native `float` **DOWNCAST is never
   flagged**: truncating a read to a narrower `float` at an aggregate/store sink is real
   precision loss (`boxGPU.h:140-142`, de≈5.8e-8) — the exact 2d-A regression the guard
   fix restored.  Same `two_limb` discipline.
2. **something promotes** (a read / Case-B write / promoted local decl) — else it is the
   *empty-payload* `promotion_no_op` class, not truncation.  The two are mutually
   exclusive by construction (this needs a landing; that fires only when none exists).
3. **every region-local decl lands at a *recognized* caller-precision type** — the
   literal `caller_type`, the `caller_complex` spelling, or a `complex_tokens` entry
   (`TOutput` → `Kokkos::complex<double>`).  A decl at an *unrecognized* template type
   (`TScale` / `TMass`) is treated as a possibly-wider persistent sink and left to
   honest build+measure.  **This is what spares `boxGPU.h:139 ff`**
   (`const TScale scalefac2 = scalefac * scalefac;`): `TScale` is unrecognized, so the
   region still measures (it is a genuine, if tiny, DISCRIM).
4. **≥1 provable caller-precision landing** — a Case-B write (always demoted to
   `caller_type` on exit) or a recognized-caller decl.  A bare `return` / expression
   with **no store is not flagged** (an extended multi-op reduction rounded once at the
   return could discriminate — conservative), so `kokkosUtils.h:212 dd`
   (`return -(S*(B0-H*B2)+A);`) stays a measurement.

Conservative by design: **flag only when provably inert (an upcast whose every store is
a caller-precision truncation), else honest build+measure.**  A false negative (missed
inert cell) just wastes one build; a false positive (gating a DISCRIM) would be a
regression — so the rule errs toward not firing.

### Soundness note

"Provably inert" here is the **structural** condition (upcast + every landing truncated
back at the boundary + no wider persistent sink), not a per-input numerical proof: an
extended multi-op RHS truncated to caller precision *could* differ from the double
computation at some input.  The gate accepts this (it matches the 2d-A examples), but is
bounded by the two hard guards that never fire wrongly — downcasts and unrecognized-type
decls are always left to honest build+measure.

## Two code paths, one detector

`kokkosUtils.h:183/212` etc. are **chain representatives** — not in the fan-out call
graph (`enclosing_function → None`), so they route to the classic `_gen_regional`
(LLM boundary) path, *not* the fan-out `promotion_no_op` gate.  The detector therefore
lives in `boundary.py` (shared) and is wired into **both**:

* **fan-out** (`fanout.py` → `FanoutResult.write_truncation`, gated in
  `dispatch._gen_regional_fanout` after the `promotion_no_op` check) — catches decl
  landings like `B2m.h:188/193 ff` (`const TOutput fac = …`).  Placement mirrors the 2c
  `promotion_no_op` gate: after the LLM shim gen, **before the build**.
* **regional / chain-rep** (`dispatch._gen_regional`, gated *before* the LLM call) —
  catches Case-B store landings like `kokkosUtils.h:183 dd` (`A = TMass(…)`).  The
  template-typed write `A` is invisible to `extract_region_writes(tracked_type=double)`,
  so a new region-local scanner `region_scan.region_writes_from_source()` recovers it.
  This path saves **both** the LLM shim gen and the build.
