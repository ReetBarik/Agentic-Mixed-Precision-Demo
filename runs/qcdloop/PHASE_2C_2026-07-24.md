# Phase 2c — empty-payload fix + honest failure gate + queue-scoped stable filter

**Date:** 2026-07-24
**Branch:** `phase2a-fanout` (commits `bdd9c28` 2c core, `c891ee3` e2e dispatch fix)
**Runs:** `runs/qcdloop/per_integral_out_b1_2c` (B1), `runs/qcdloop/per_integral_out_b12_2c` (B12);
5000 samples, `--fanout`, tol=10, `--max-iters` 8 (B1) / 12 (B12).
**Tests:** 497 green (was 495 after 2c code; +2 dispatch guards).

---

## TL;DR

2c did what it set out to do. The **structural empty-payload bug is fixed** and the
**honest failure gate works** (24 `promotion_no_op` firings across the two runs, all
legitimate). The reframe now produces **real, rung-discriminating deltas** where a
scalar payload exists (B1: 5 discriminating, 0 inert). B1's correctness half is now
**honestly empty** instead of 8 inert clone-cells.

The high-signal integral (B12) did the more interesting thing: with the empty-payload
class removed, it **exposed a second, distinct inertness class — write-boundary
truncation** (a dd/ff-promoted RHS truncated back to `double`/`TOutput` on store or
return). These are *non-empty* promotions that build and run but leave the output
unchanged; the scorer now reports them honestly as `delta==baseline` rather than as
byte-identical clones. That is the correct 2c outcome, and it cleanly scopes the next
problem.

## What shipped (recap)

1. **2c-A — source-derived reads** (`agents/shared/region_scan.py::region_reads_from_function`,
   wired into `agents/patcher/fanout.py`). When an intent carries no `variables`, the
   Patcher derives the region's scalar reads (float/template params + body locals) by
   token scan. Feeds both the variant and in-place promotion paths.
2. **2c-A — `promotion_no_op` gate** (`fanout.py` computes `promotion_applied`;
   `dispatch.py::_gen_regional_fanout` returns terminal `PROMOTION_NO_OP` on an
   empty payload). A variant byte-identical to the original is now a terminal failure,
   not a silent measured cell.
3. **2c-B — queue-scoped stable filter** (`agents/strategy/ranking.py`). The
   correctness queue drops `signal_class="stable"`; the speedup queue keeps stable
   regions (they are the right demotion targets).
4. **Wiring:** `promotion_no_op` added to `result.STATUSES`, the scorer status map,
   the manifest failure-prefix set, and — the e2e fix — the Strategy **dispatch table**
   (`agents/strategy/dispatch.py`), plus a `set(DISPATCH)==set(STATUSES)` exhaustiveness
   test so the tables can never drift silently again.

### e2e blocker found & fixed (`c891ee3`)

The first e2e attempt aborted both passes in <13 min with
`unknown Patcher status 'promotion_no_op'`. Root cause: the new status was registered
in four places but **not** in the Strategy dispatch table. The 495-green unit suite
missed it because `test_all_statuses_present` hardcoded its expected set instead of
comparing to `result.STATUSES`. Fixed the entry + added the drift guard.
`DISPATCH['promotion_no_op']` mirrors `llm_gen_failed`: `advance_terminal` (no rung
would promote an empty payload), `counts_budget=False` (git-only, no build),
`is_reject=True`, `dd_untested=True`.

| | 2b (`per_integral_out_b1_2b`) | 2c (`per_integral_out_b1_2c`) |

| status | insufficient_fix | success |

**Interpretation.** In 2b every B1 cell was a byte-identical clone
(`delta==baseline==6.942e-13`). In 2c:

- The correctness half is **honestly empty** — B1's 35 regions are all `signal_class=
  stable` with no error to fix, so 2c-B correctly queues nothing there. The 8 inert
  cells are gone, not hidden.
- The **speedup half became the star**. The 2c-A derived-reads fix turned the
  previously-empty `boxGPU.h:139-142` promotions into real payloads that build and
  measure. Region 139 discriminates rungs cleanly:

  | region 139 | rung | delta_effective | baseline |
  |---|---|---|---|
  | `double-to-float` | float | **1.690e-07** | 6.942e-13 |
  | `double-to-ff` | ff | **6.904e-13** | 6.942e-13 |

  float is measurably too lossy (1.7e-7 of added error); ff is essentially lossless
  (−3.9e-15 vs baseline). This is the reframe working exactly as designed.

- 10 `promotion_no_op` firings (boxGPU.h:99-101, 114-115) are **correct**: those lines
  touch only `xpi[...]` (a `View`/array aggregate, deliberately excluded from scalar
  promotion), so the derived scalar-read set is genuinely empty. The gate distinguishes
  them from the scalar-read lines (139-142 = `scalefac`/`scalefac2`) that *do* build.

## B12 — first look (high-signal, non-empty correctness)

Status `budget_exhausted` (hit `--max-iters 12` on real builds, as expected).
`failure_modes = {ok:12, promotion_no_op:14, llm_gen_failed:13}`; 9 correctness
decisions + 30 speedup. Baseline_delta = **2.039e-04** everywhere — B12's own
cancellation error, correctly captured per-integral (vs the whole-app B12 ~2e-4).

Scorer: 12 measured, **10 inert, 2 discriminating**.

- `boxGPU.h:139` `double-to-float` → delta 2.03897e-4 vs base 2.03880e-4
  (**+1.75e-08**, non-inert): float adds a bit of error, negligible against B12's
  dominant 2e-4 cancellation. This is the one clean non-inert rung-discriminating delta.
- `boxGPU.h:139` `double-to-ff` → −2.45e-16 (last-bit): ff lossless, as on B1.

The **10 inert cells are the finding.** They are *not* empty-payload clones (those
became the 14 `promotion_no_op`); they are **non-empty promotions that build, run, and
leave the output bit-identical** because the extra precision is truncated at the write
boundary:

- `kokkosUtils.h:183` — `A = TMass( … kPow(kLog(1+T),2) … )`. The dd-promoted RHS is
  cast **back to `TMass` (double) on store** to `A`.
- `kokkosUtils.h:212` — `return -(S * (B0 - H * B2) + A)`. This *is* a cancellation
  (`B0 - H*B2`), but the dd interior is truncated on the `TOutput` return.
- `kokkosUtils.h:231-232, 369` — `TOutput` (complex) ff/float. **These built** — the
  feared complex-dd compile failure did not materialize; inertness did instead, again
  via store truncation.

The `promotion_no_op` gate correctly *passes* these (the promoted region text is not
byte-identical), and the scorer honestly reports `delta==baseline`. So the inertness is
now **visible with a clear signal**, not a silent clone. Distinguishing
`promotion_no_op` (empty → patcher_failed) from `measured & delta==baseline` (non-empty,
no effect) from `measured & discriminating` is exactly the richer, honest manifest 2c
was meant to deliver.

## Handoff notes

**Reads-derivation approach — token scan, not libclang.** Reads need no AST type
resolution, and libclang cannot resolve a template region's types without its include
context anyway (the same reason `extract_region_writes` relies on its fallback lexer in
practice). The scan classifies each param/local by its *core* (outermost) type spelling,
so `Kokkos::Array<...TMass...>` resolves to `Array` (aggregate, excluded), not the inner
`TMass`. Validated against real qcdloop regions:
`boxGPU.h:139 → [scalefac]`, `139-142 → [scalefac, scalefac2]`,
`B0m.h:126 → [fac, lnrat_tamu2, lnrat_simu2, lnrat_tasi]` (int index `i` excluded).

**Where source-derived reads was empty (correctly).** Every `promotion_no_op` firing
inspected was a region touching only aggregate elements (`xpi[...]`) or with no scalar
RHS. This is a **scope boundary, not a bug**: aggregate/array promotion is out of the
current region-granular-scalar design. A future phase that promotes `View`/`Array`
storage would revisit exactly these regions. No under-derivation (missing a real scalar
read) was observed; the scan discriminates scalar-read from aggregate-only lines within
the same file.

**Did the reframe discriminate rungs cleanly?** On B1, yes — beautifully
(float 1.7e-7 vs ff 6.9e-13 at the same region). On B12, the *rung* discrimination is
present but small because B12's 2e-4 cancellation dwarfs the ff/float demotion cost; the
more important signal there is the **inert-vs-discriminating** split on the correctness
dd cells, which surfaced the write-boundary-truncation class.

**Surprises.**
1. B1's **speedup** half, not its correctness half, was the biggest immediate win from
   2c-A — the derived-reads fix unblocked real measurement on `boxGPU.h:139-142`.
2. B12 exposed a **second inertness class**: write-boundary truncation (non-empty dd/ff
   promotion, output unchanged because the store/return truncates to double). Distinct
   from the empty-payload class 2c fixed.
3. **Complex `TOutput` ff/float promotions built** — the pre-run concern that dd/ff of
   complex operands might fail compilation did not occur; they compile and run, they are
   just inert via truncation.

**Recommendation: 2d (float-hardening) before 2e (solver).** 30 `llm_gen_failed` across
the two runs (17 B1 + 13 B12) means the ff/float rungs are largely **not even being
measured** — the measurement supply is gen-limited. A solver (2e) built now would run on
sparse, mostly-failed data. Fix the ff/float Patcher-gen gap first (2d) to populate the
manifest with measured cells, *then* build the decision layer on top of a dense signal.

**Joint-measurement flag — relevant, not yet urgent.** B12's write-boundary-truncation
inertness says that fixing correctness on a cancellation integral needs to promote a
**variable's declaration together with its uses** (or a contiguous span through the
store/return), not a single RHS in isolation. That is a joint / multi-line concern and
belongs with Phase 3 line-granular work — but it is **gated behind 2d**: without ff/float
gen working there is little joint measurement to do. Recommend addressing it inside
Phase 3 rather than standing up a separate joint-measurement machine now.

**Next-phase candidate gate (not 2c scope).** A cheap, honest follow-on to the
`promotion_no_op` gate: a *write-truncation* detector — if every write target of a
promoted region is declared at the narrower type (so the promoted RHS is provably
truncated on store), flag it rather than spend a build measuring a guaranteed-inert cell.
This would convert B12's 10 inert measured cells into cheap terminal failures, mirroring
what `promotion_no_op` did for empty payloads.
